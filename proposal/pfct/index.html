Credit DecisionOps Copilot
여신 업무 판단 근거 자동화와 HITL 검수 시스템

PFCT의 온투금융 운영 경험, AIRPACK의 리스크 분석·룰셋·배포·모니터링 흐름, 그리고 통합여신시스템 확장 방향을 전제로 작성한 가설 기반 AX 프로젝트 기획서입니다. 목표는 AI가 최종 판단을 대체하는 것이 아니라, 금융 담당자가 더 빠르고 정확하게 판단하도록 근거 수집·정리·검수·피드백 루프를 시스템화하는 것입니다.

Project Type: Internal AX → Productizable Module Domain: Lending · Credit Risk · Loan Operations Track: Agentic System + Ontology/Retrieval + Backend Scope: Hypothesis → Architecture → Deployment
Executive Thesis

공개 자료 기준 PFCT에서 AX 임팩트가 클 것으로 가정하는 지점은 단순 문서검색이 아니라, 여신 심사·한도/금리 산정·채권관리·운영 대응 과정에서 흩어진 판단 근거를 모아 사람이 검수 가능한 실행 단위로 구조화하는 구간입니다.

따라서 본 제안은 AI Agent가 대출 판단을 직접 확정하는 시스템이 아니라, 케이스별 데이터·정책·룰·모델 결과·유사 사례·사후 성과를 모아 Evidence Pack을 생성하고, HITL 검수와 평가 로그를 통해 지속 개선되는 DecisionOps 시스템을 목표로 합니다.

02 · Hypothesis Driven Plan

병목 가설과 검증 플랜

AX 프로젝트의 실패 원인은 “AI 기능을 만들었지만 업무 병목을 줄이지 못하는 것”입니다. 따라서 먼저 업무 시간을 실제로 잡아먹는 지점을 계량하고, 작은 단위에서 검증한 뒤 자동화 범위를 확장해야 합니다.

가설예상 병목검증 방법성공 기준
H1. 판단 근거 수집 비용 담당자가 고객 데이터, 정책 문서, 모델 결과, 유사 사례를 여러 시스템에서 수동 조회 심사/운영 케이스 30~50건의 작업 로그를 샘플링하고 케이스 준비 시간을 측정 Evidence Pack 도입 후 준비 시간 30%+ 감소
H2. 정책·룰 변경 설명 비용 룰셋 변경 시 승인율·부실률·고객군 영향 설명이 반복 문서 작업으로 발생 과거 룰 변경 티켓/문서의 필수 설명 항목을 추출하고 자동 생성 결과와 비교 필수 설명 항목 회수율 90%+, 담당자 수정률 40% 이하
H3. 검수 기준 불균일 수동 심사/채권관리 케이스에서 담당자별 확인 항목이 달라짐 케이스 유형별 체크리스트를 정의하고 누락 데이터·red flag 자동 탐지 필수 근거 누락률 50%+ 감소
H4. 사후 성과 피드백 단절 AI/룰/사람 판단 결과가 이후 연체·회수·민원 결과와 충분히 연결되지 않음 DecisionCase와 PostOutcome을 연결해 검수 결과별 사후 성과를 추적 케이스별 근거·결정·사후성과 재현율 95%+
H5. 자동화 리스크 AI가 고위험 케이스를 과도하게 자동화하면 규제·신용·평판 리스크 증가 고위험 조건을 정책 기반 guardrail로 정의하고 자동화 제외 경로를 강제 고위험 케이스 완전 자동승인 0건

04 · Technical Architecture

기술 아키텍처

설계 원칙은 세 가지입니다. 첫째, 정형 데이터와 문서 검색을 분리하지 않고 케이스 단위 컨텍스트로 결합합니다. 둘째, AI 출력은 항상 근거와 함께 저장합니다. 셋째, 고위험 케이스는 HITL 검수 큐를 우회할 수 없습니다.

정형 데이터, 정책/룰 문서, 모델 결과, 유사 케이스를 케이스 단위 컨텍스트로 결합하고, AI 출력은 Evidence Pack과 HITL Review를 거쳐 감사·평가 저장소로 축적합니다.
핵심 컴포넌트
Case Router
심사 예외, 룰 변경 검토, 연체 조기경보, 운영 문의 등 케이스 유형을 분류하고 우선순위를 부여합니다.
Context Builder
SQL/API, BM25, 벡터 검색, 모델 결과 저장소를 호출해 케이스별 컨텍스트 패키지를 만듭니다. 모든 근거에는 source_id, version, valid_at을 붙입니다.
DecisionOps Agent
근거 요약, 누락 데이터 체크, red flag 분류, 유사 사례 비교, 검토 체크리스트, 액션 후보를 생성합니다.
HITL Review Queue
담당자가 승인/수정/반려/추가 데이터 요청/escalation을 수행합니다. 고위험 케이스는 반드시 이 큐를 통과합니다.
Audit & Eval Store
입력 컨텍스트, 생성 결과, 사람 수정 내역, 최종 결정, 사후 성과를 연결해 품질 평가와 지속 개선의 기반으로 사용합니다.
05 · Data Model & API Contract

06 · Evaluation & HITL

평가 지표와 HITL 루프

금융 업무에서 LLM 응답의 자연스러움은 핵심 지표가 아닙니다. 중요한 것은 근거 누락이 줄었는지, 담당자의 검토 시간이 줄었는지, 정책 위반이 없는지, 사후 성과와 연결해 품질을 개선할 수 있는지입니다.

Offline Evaluation
과거 케이스의 실제 검토 문서와 담당자 판단 로그를 golden set으로 삼아 근거 회수율, 정책 정합성, 요약 누락률, red flag 탐지율을 측정합니다.
Online Evaluation
실제 업무에서 준비 시간, 채택률, 수정 유형, 재작업률, 사후 성과를 추적합니다. A/B 또는 staged rollout으로 효과를 검증합니다.

HITL 피드백 루프
1. AI 생성
Evidence Pack과 추천 액션 후보를 생성합니다. 모든 문장에는 가능한 경우 근거 source_id를 연결합니다.
2. 사람 검수
담당자는 승인, 수정, 반려, 추가 데이터 요청, escalation 중 하나를 선택합니다.
3. 수정 사유 구조화
수정 이유를 누락 데이터, 정책 오해, 부정확한 요약, 위험 과소평가, 문장 톤 등 reason code로 저장합니다.
4. 평가 데이터 축적
수정 내역과 사후 성과를 연결해 retrieval 품질, 정책 문서 최신성, 프롬프트/룰 개선 우선순위를 결정합니다.
07 · Operation & Deployment

운영·배포 플랜

금융 도메인의 AX 시스템은 기능 출시보다 안전한 운영 경계가 먼저입니다. 개인정보(PII) 보호, 정책 버전, 감사 로그, 비용·지연 모니터링, rollback 가능성을 초기 설계에 포함해야 합니다.

배포 전략
Phase 0Read-only shadow mode. 실제 업무에 영향 없이 과거/실시간 케이스에 Evidence Pack을 생성하고 담당자 결과와 비교합니다.
Phase 1Limited pilot. 특정 케이스 유형과 소수 담당자에게만 HITL Queue를 제공합니다.
Phase 2Feature flag rollout. 케이스 유형, 리스크 레벨, 담당 부서별로 기능을 점진 활성화합니다.
Phase 3Productization bridge. 내부 AX에서 검증된 모듈을 AIRPACK 또는 통합여신시스템 확장 기능으로 분리 가능한 계약을 설계합니다.
운영 가드레일
PII필드 단위 masking, access scope, retrieval 권한 제어
정책 최신성valid_at, version, owner가 없는 정책은 사용 금지
고위험 케이스완전 자동화 금지, 강제 HITL 라우팅
감사입력 컨텍스트와 출력, 사람이 수정한 내용, 최종 결정 snapshot 저장
비용케이스 유형별 LLM 호출량, 검색 비용, latency budget 추적
권장 기술 스택

CI/CD와 릴리즈 절차
PR Gate
prompt/template 변경, policy parser 변경, retrieval index 변경은 golden set regression test를 통과해야 merge합니다.
Index Release
정책 문서 index는 versioned release로 배포합니다. 신규 index는 shadow evaluation 후 promote합니다.
Canary
부서/케이스 유형/리스크 등급 단위로 canary rollout합니다. Critical omission rate가 임계값을 넘으면 자동 rollback합니다.
Rollback
API feature flag, prompt version, retrieval index version, policy parser version을 독립적으로 rollback할 수 있게 설계합니다.
08 · Roadmap & Risk Management

MVP 로드맵과 리스크 관리

초기 목표는 거대한 Agent 플랫폼이 아니라, 실제 업무 시간을 줄이는 작은 문제를 2~4주 단위로 검증하는 것입니다. 각 단계는 kill criteria를 가져야 하며, 성공한 모듈만 다음 단계로 확장합니다.

Sprint 0 · 업무 관찰과 베이스라인 측정
1~2주 · No-code/low-code research
케이스 유형별 담당자 작업 흐름을 관찰하고, 준비 시간, 참조 시스템, 필수 근거 항목, 자주 누락되는 데이터, 규제/정책 guardrail을 정리합니다. 이 단계에서 자동화 대상과 금지 대상을 명확히 분리합니다.
Sprint 1 · Evidence Pack Generator MVP
2주 · Read-only shadow mode
과거 케이스 또는 실시간 shadow 케이스에 대해 근거 패키지를 생성합니다. 실제 업무 결정에는 사용하지 않고 담당자 결과와 비교합니다.
Sprint 2 · HITL Review Queue
2~3주 · Limited pilot
담당자가 AI 결과를 승인/수정/반려하고, 수정 사유를 reason code로 저장하는 UI/API를 제공합니다. 이때부터 업무 시간 감소와 채택률을 측정합니다.
Sprint 3 · Rule Change Review Assistant
3~4주 · 리스크/정책 담당자 대상
룰셋 변경 diff, 영향 고객군, 예상 KPI, 배포 체크리스트를 자동 생성합니다. AIRPACK의 분석·룰셋·배포 흐름과 연결 가능한 인터페이스를 설계합니다.
Sprint 4 · Evaluation Dashboard & Productization Bridge
3~4주 · 운영 지표 고도화
채택률, 수정률, 정책 누락, 비용, latency, 사후 성과를 대시보드화합니다. 내부 AX에서 검증된 Evidence Pack/HITL/Audit 모듈을 외부 제품 기능으로 분리 가능한 boundary를 정의합니다.
리스크와 대응 전략
리스크문제대응
Hallucination근거 없는 정책/숫자 생성근거 source_id 없는 문장 표시 금지, citation-required template, structured output validation
Stale Policy만료된 정책 문서 참조valid_at/version/owner 없는 문서 retrieval 제외, index release approval
Wrong Automation고위험 케이스를 자동 처리 후보로 잘못 분류risk guardrail rule 우선 적용, high-risk forced HITL, 자동승인 비활성
PII Leakage민감정보가 불필요하게 모델/로그에 노출field masking, purpose-based access, encrypted audit store, prompt logging redaction
Metric Gaming검토 시간만 줄이고 품질이 악화시간 절감 지표와 critical omission, 사후 성과, 재작업률을 함께 평가
Operational CostLLM 호출 비용/지연 증가case complexity routing, caching, smaller model for summarization, retrieval prefilter
최종 제안 문장
Project Thesis
PFCT의 AX는 “AI 챗봇 도입”에 그치지 않고, 여신 업무의 판단 근거와 실행 흐름을 사람이 검수 가능한 시스템으로 바꾸는 방향으로 확장될 때 가장 큰 임팩트를 만들 수 있다고 생각합니다. Credit DecisionOps Copilot은 크플의 실제 온투금융 운영 경험과 AIRPACK의 분석·룰셋·배포·모니터링 흐름을 연결해, 내부 생산성 개선과 외부 제품화 가능성을 동시에 검증할 수 있는 AX Squad 프로젝트입니다.
